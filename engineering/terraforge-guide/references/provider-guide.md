# TerraForge Provider Guide

## What is a Provider?

A provider tells TerraForge how to connect to a data source. There are two built-in providers:

- **rest_api** -- connects to any HTTP/REST endpoint
- **local** -- creates files and directories on your machine (no network)

---

## REST API Provider

### Minimal Config

```hcl
provider "rest_api" {
    base_url = "https://api.example.com"
    api_key  = "your-key-here"
}
```

### Fields

| Field      | Required | Description                                    |
|------------|----------|------------------------------------------------|
| `base_url` | yes      | Root URL of the API (no trailing slash)         |
| `api_key`  | no       | Bearer token or API key for authentication      |
| `headers`  | no       | Additional HTTP headers as key-value pairs      |
| `timeout`  | no       | Request timeout in seconds (default: 30)        |

### Using Saved Keys

Instead of putting your key in the `.tf` file, save it securely:

```bash
terraforge key set rest_api sk-live-abc123
```

Then omit `api_key` from the provider block -- TerraForge will use the saved key automatically.

### Resource Block

```hcl
resource "rest_api_resource" "users" {
    endpoint = "/api/v1/users"
    method   = "GET"
}
```

| Field      | Required | Description                                |
|------------|----------|--------------------------------------------|
| `endpoint` | yes      | Path appended to `base_url`                |
| `method`   | yes      | HTTP method: GET, POST, PUT, DELETE        |
| `body`     | no       | JSON request body (for POST/PUT)           |
| `params`   | no       | Query string parameters as key-value pairs |

### Multiple Resources

You can define as many resources as you need in one file:

```hcl
provider "rest_api" {
    base_url = "https://jsonplaceholder.typicode.com"
}

resource "rest_api_resource" "posts" {
    endpoint = "/posts"
    method   = "GET"
}

resource "rest_api_resource" "users" {
    endpoint = "/users"
    method   = "GET"
}

resource "rest_api_resource" "comments" {
    endpoint = "/posts/1/comments"
    method   = "GET"
}
```

Each resource becomes a separate JSON file in the `data/` directory after apply.

## Local Provider

The local provider creates files and directories on your machine. Useful for scaffolding, templating, or testing without any network.

### Minimal Config

```hcl
provider "local" {}
```

### Directory Resource

```hcl
resource "local_directory" "project_dir" {
    path = "output/my-project"
}
```

### File Resource

```hcl
resource "local_file" "readme" {
    filename = "output/my-project/README.md"
    content  = "# My Project\nGenerated by TerraForge."
}
```

## Real-World Examples

### GitHub API

```hcl
provider "rest_api" {
    base_url = "https://api.github.com"
    api_key  = "ghp_your_token_here"
}

resource "rest_api_resource" "repos" {
    endpoint = "/user/repos"
    method   = "GET"
}
```

### JSONPlaceholder (Free Test API)

```hcl
provider "rest_api" {
    base_url = "https://jsonplaceholder.typicode.com"
}

resource "rest_api_resource" "posts" {
    endpoint = "/posts"
    method   = "GET"
}
```

### Custom Internal API

```hcl
provider "rest_api" {
    base_url = "http://localhost:8000"
    api_key  = "ast_demo_key_12345"
}

resource "rest_api_resource" "assets" {
    endpoint = "/api/v1/assets"
    method   = "GET"
}

resource "rest_api_resource" "create_asset" {
    endpoint = "/api/v1/assets"
    method   = "POST"
    body     = <<EOF
{
    "name": "New Asset",
    "type": "document"
}
EOF
}
```

## Tips

1. Keep one provider per `.tf` file for clarity.
2. Use `terraforge key set` for real API keys -- never commit keys to version control.
3. The `data/` folder is auto-created on `apply`. Check it for raw JSON responses.
4. Use `terraforge export` to create a single `terraforge_export.json` snapshot of all collected data.
5. The state file (`terraforge.tfstate`) tracks what was created so `destroy` can undo it -- do not edit it by hand.
